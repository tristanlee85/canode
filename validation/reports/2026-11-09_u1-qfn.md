# U1 package change: LQFP-48 → UFQFPN-48 (2026-11-09)

**Why.** STM32G0B1CBT6 (LQFP-48, C2847904) had 0 stock at JLC and LCSC with a pre-order backlog and no ETA; every
LQFP-48 G0B1/G0C1 listing was also at 0 (`2026-11-09_lcsc.md`). T chose to switch to the **STM32G0B1CEU6**
(UFQFPN-48 7×7 mm, 512 KB flash, C2829190, ~400–500 in stock).

## Pin compatibility
- ST's open pin data: `STM32G0B1C(B-C-E)Tx.xml` (LQFP48) and `…Ux.xml` (UFQFPN48) list **identical** names/types on all 48 pins.
  (The "…N" variants differ, e.g. pin 30 = VSS, and were not used.)
- Exposed pad: ST's same-package datasheets recommend soldering it to PCB ground. Added as **pin 49 (VSS)** to the
  embedded U1 symbol, stacked on pin 7 (VSS) so it shares that pin's GND label stub. `make pins` now checks the UFQFPN data:
  29/29 including "pin 49 exposed pad: on GND".
- Netlist and firmware are unchanged (same pin numbers; the 128 KB linker script runs on the 512 KB part).

## Board changes
- Footprint: `Package_DFN_QFN:QFN-48-1EP_7x7mm_P0.5mm_EP5.6x5.6mm` (EP size per ST's UFQFPN48 drawing, 5.5–5.7 mm),
  same position and rotation as the LQFP. The library's `_ThermalVias` variant was not used: its 0.2 mm drills are
  below this board's 0.3 mm minimum hole size. Instead a **3×3 grid of 0.6/0.3 mm GND vias** (1.6 mm pitch) sits in the pad.
- The rev A autoroute ran ~20 signals and vias *under* the LQFP body, where the QFN's exposed pad now is. Re-route:
  every U1 signal net (24) plus anything inside a ±5.6 mm box around U1 was ripped up; all other copper was locked
  and kept; Freerouting 2.1 routed the gaps; only the router's new (non-protected) wiring was imported.
- J5 pad 6 (GND) set to a solid zone connection: a new B.Cu track left room for only one thermal spoke.
- 3D model paths moved to `${KICAD10_3DMODEL_DIR}` (`.step`); J1/J2/SW1/SW2 use the stand-ins in `hardware/3dmodels/`.
  U1 uses the EP5.15 QFN-48 model (same 7×7 body; KiCad ships none for EP5.6).

## Verification
- `make check`: pins 29/29, ERC 0 errors, DRC **0 errors, 0 unconnected, parity clean** (50 footprint-library-version warnings).
- `make fab`: CPL identical to the previous one (U1 position/rotation unchanged); BOM changes are exactly the intended swaps.
- At order time, check U1's pin-1 corner in JLC's placement preview. QFN pin-1 marks are easy to misread.

## Process notes (for whoever re-routes next)
KiCad 10's bundled `pcbnew` SWIG objects go stale in long scripts (`GetTracks`/`GetConnectivity` start returning bare
`SwigPyObject`s), and `GetNetsByName` no longer works. Do one step per process, and count unconnected items with `kicad-cli pcb drc`.
Freerouting's SES omits some protected wiring, so import only non-`protect` wires/vias and keep the board's own copper.
